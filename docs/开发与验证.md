## 本地行为检查

以下命令从仓库根目录执行。配置`ANDROID_HOME`与可运行Gradle的JDK；Kotlin/Native测试需要macOS、Xcode及iOS Simulator运行环境。Node测试转译真实ArkTS源码并使用受控SDK替身，`TYPESCRIPT_PATH`可指定已有TypeScript模块。

```sh
bash gradlew :system-actions-core:testDebugUnitTest :system-actions-core:jvmTest --max-workers=1
node ohos/tests/system-actions.test.cjs
node ohos/tests/system-actions-module.test.cjs
node ohos/tests/native-store.test.cjs
node ohos/tests/file-actions.test.cjs
node ohos/tests/keep-screen-module.test.cjs
node ohos/tests/system-observations.test.cjs
```

只运行受影响目标；需要确认本轮真实执行时加`--rerun-tasks`，不要把`UP-TO-DATE`算成新执行。平台测试结果XML位于`system-actions-core/build/test-results/`。这些测试不调用真实分享、认证、拨号或定位业务。

## 原生产物与独立消费

Swift-only `1.0.0` 使用原生 tag `native-1.0.0`，Maven `1.0.0` / HAR `1.0.0` 保持。现有 `regression.yml` 在该 tag 的 Release 或精确 version dispatch 执行 `release-swift`：独立工程从远端 tag 安装 `GYCWindowPolicy/Core`，核对 Pod 版本、source tag 和全部 Swift 源码 SHA-256 与冻结 checkout 一致，真实 Simulator UIKit SDK 编译 Pod，再 typecheck [旧方法引用和新 overload](../verification/KeyboardObservation.swift)。成功后输出 `ci-diagnostics/swift-pod-proof.json`；不复用本地 Pod、Maven、HAR 或宿主源码。

入口为 `scripts/ci-verify-swift-pod.py --tag native-1.0.0 --build-dir <全新绝对目录> --proof <回执路径>`，原生构建只在 CI 执行；本机可运行 `PYTHONDONTWRITEBYTECODE=1 python3 verification/ci/test_swift_pod.py` 验证版本/来源/嵌套源码缺失、修改和新增的拒绝边界。原 `native-0.2.0-rc.7` 仅 HAR 发布，不进入此 Swift job；普通 Maven Release 路径保持不变。最终发布、精确 SHA 与远程执行结果以对应 Release 为准，编译不等于宿主或设备验收。

HarmonyOS工具链需要DevEco SDK、ohpm与hvigorw。在`ohos/`目录执行：

```sh
ohpm install --all
hvigorw --mode module -p module=SystemActionsNative@default -p product=default assembleHar --no-daemon
```

安装与公开API消费工程按[接入指南](接入指南.md)和[README](../README.md)执行。构建/本地HAR消费不等于OHPM Registry或本版远程消费。Maven、Swift/Pod与HAR按各自版本验证。

## Native Module 验证

本版源码 Maven / Git Pod `1.0.0`；发布及远程消费状态以对应 Release 证据为准。仅在独占 Worktree 操作；当前验证基线为 Kuikly Maven `2.29.1-2.0.21-ohos` / iOS Pod `OpenKuiklyIOSRender 2.29.1`。

```bash
ANDROID_HOME=/Users/guoyang/Library/Android/sdk ./gradlew \
  --init-script scripts/ci-repositories.gradle \
  :system-actions-kuikly:testDebugUnitTest \
  :system-actions-kuikly:compileDebugKotlinAndroid \
  :system-actions-kuikly:compileKotlinIosArm64 \
  :system-actions-kuikly:compileKotlinIosSimulatorArm64 \
  :system-actions-kuikly:compileKotlinOhosArm64 --max-workers=1 --no-parallel
bash scripts/ci-build-kuikly-render.sh "$PWD/build/kuikly-native-pod" GYCWindowPolicy/Kuikly
```

handler 行为回归与真实 SDK receiver 测试在 [`system-actions-kuikly/src/androidUnitTest`](../system-actions-kuikly/src/androidUnitTest)。handler 使用受控原生动作/播放器；receiver 继承真实 SDK，验证注册工厂、独占 owner、Main 排队后销毁与迟回调资格，不打开真实系统页面或播放网络音频。

本轮 iOS Pod source install + xcodebuild 已在 Simulator arm64 完整编译链接通过，含真实 SDK 与组件 receiver；Swift 单独 typecheck 也通过。Android/iOS/OHOS Kotlin 最终编译与测试结果以本轮报告为准，不复用旧测试数量冒充新增测试执行。

源码 CI 沿用原 Android/native job：Android 执行新 receiver/handler 测试；native 编译新增 Kotlin iOS target、旧 OHOS target，并用上述单次 Pod build 编译 SDK 与 receiver。正式 ReleaseNative 对新版本读取精确远程 Maven、以同一 Git tag 构建远程 Pod，然后以真实生成的 consumer framework 编译 [`KuiklyAssembly.swift`](../verification/KuiklyAssembly.swift)。旧版本 consumer 与 publication 清单保留原合同。

精确远程 Maven/Git Pod 消费以对应 Release 证据为准；宿主 Shared 导出/注册与真机行为需单独验收。iOS Pod 不携带 KMP framework，宿主必须把 handler 从既有 Shared framework 导出；装配探针不是第二个生产 runtime。

source Native 门禁先调用 `scripts/test-ios-module.sh --prepare-simulator` 创建并启动本轮独占 Simulator，让启动与缓存恢复、编译重叠。Pod 构建后执行 `scripts/test-ios-module.sh Products目录 设备UUID`，仍等待设备 ready、重新编译并安装测试 App，使用真实 SDK/组件 framework 验证重复 `invalidate`、SDK `dealloc`、销毁前已排队调用和 off-Main 释放；原 PASS 断言与超时不变。CI 的 `always()` 步骤删除本轮设备，准备失败时脚本自行清理；不操作宿主已有设备。

不传设备 UUID 的独立调用仍自行创建、等待并清理设备。`LIFECYCLE_PHASE` 输出编译、签名、创建、启动、ready、安装、launch/PASS 和清理边界；`elapsed_seconds` 是本次脚本调用累计秒数，相邻边界相减得到阶段耗时，跨脚本用 UTC 时间对齐。离线替身检查 `python3 verification/ci/test_ios_module_simulator.py` 不启动真实 Simulator，不代替远程源码门禁。

## 源码 CI 编译缓存

源码 `android/native` jobs 使用固定 SHA 的 `gradle/actions/setup-gradle` 复用 Gradle User Home，并通过现有 init script 启用编译缓存。PR 只读缓存，完整源码 dispatch 与 main 可写入当前 ref 的缓存；源码修改仍由 Gradle 输入指纹决定是否重编译。仅工具链预热不恢复或保存此 Gradle 缓存，避免先占用同 SHA 的不可变 key 而阻止后续源码结果写入。

`AbstractTestTask` 禁用缓存及 up-to-date 跳过，行为测试每次实际执行；原编译目标、Simulator/Swift 检查、链接、超时与门禁保持不变。发布 jobs 不启用本策略，保留原精确版本及依赖刷新验证。冷暖耗时必须绑定同一 SHA 与完整源码运行，不能把缓存预热或普通 main push 的轻量检查算作源码通过。
