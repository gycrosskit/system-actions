# System Actions 开发与验证

消费者安装与调用见 [README](../README.md) 和[接入指南](接入指南.md)，历史验收见[验收记录](../verification/验收记录.md)。以下命令在仓库根目录执行。

原生商店的发布前检查与产物边界见[原生商店候选验收](../verification/原生商店候选验收.md)，当前远程发布与审核状态见[远程发布验收](../verification/远程发布验收.md)。

## 最小验证

```sh
bash gradlew :system-actions-core:jvmTest :system-actions-core:testDebugUnitTest \
  :system-actions-core:compileKotlinIosSimulatorArm64 :system-actions-kuikly:compileKotlinOhosArm64
node ohos/tests/system-actions.test.cjs
node ohos/tests/system-actions-module.test.cjs
node ohos/tests/native-store.test.cjs
```

HAR 测试使用 TypeScript 转译器，可通过 `TYPESCRIPT_PATH` 指定模块。测试覆盖非法输入、等待受理、系统失败、设置包名、取消/销毁和迟到回执；原生商店额外覆盖厂商/固定包名、URI fallback、onAppear/onError/onDisappear、20 秒超时、取消、ID 重用与共享 owner。mock 不能替代真实系统页面验收。

安装 DevEco SDK，并将 `tools/node/bin`、`tools/ohpm/bin`、`tools/hvigor/bin` 加入 `PATH` 后，在 `ohos` 中执行 `ohpm install --all` 与 `hvigorw assembleHar --no-daemon`。产物为 `system-actions-native/build/default/outputs/default/SystemActionsNative.har`。

## 独立消费与发布

```sh
bash gradlew -p verification-consumer compileDebugKotlinAndroid \
  compileKotlinIosArm64 compileKotlinIosX64 linkDebugFrameworkIosSimulatorArm64 compileKotlinOhosArm64
cd verification-ohos
ohpm install --all
hvigorw assembleHar --no-daemon
```

默认从 JitPack / OHPM Registry 获取远程版本，不引用本库源码。本地发布前执行 `bash gradlew publishAllPublicationsToStagingRepository`，再用 `-PsystemActionsRepository=<staging Maven 目录>` 验证；临时 HAR file 依赖只证明产物消费，不能代替 Registry 安装验收。

全变体 Maven 在 macOS 构建，按不可变标签上传 Release 归档，JitPack 下载并校验 SHA-256；发布配置见根目录 `jitpack-install.sh` / `release-checksums.txt`。归档前运行 `scripts/jitpack-metadata.py` 正规化 metadata 并重算校验，再运行 `scripts/check-maven.py`；JitPack 仅下载校验并安装同一归档字节，不依赖旧 Python 改写 metadata。HAR 和 Maven 分别版本化，不能从 Maven 版本推断 HAR 版本。

现有记录覆盖远程 Maven 编译、iOS Simulator Framework 链接，以及精确 OHPM Registry 版本安装与独立 `assembleHar`。真实拨号、商店、系统设置及 Kuikly 设备页面生命周期仍待验收。

## Window 策略验证

`0.2.0-rc.1` 已预发布，远程矩阵已通过，详情见[Window 预发布验收](../verification/Window策略候选验收.md)。本地构建入口如下。按通道分别验证，不能用 HAR 成功证明 Swift/UIKit 正常。

```sh
bash gradlew :system-actions-core:testDebugUnitTest --tests '*AndroidWindowPolicyTest'
node ohos/tests/window-policy.test.cjs
bash ios/Tests/run.sh
xcodebuild -scheme GYCWindowPolicy -destination 'generic/platform=iOS Simulator' -derivedDataPath build/swift-package CODE_SIGNING_ALLOWED=NO build
cd verification-ios
xcodebuild -scheme WindowPolicyConsumer -destination 'generic/platform=iOS Simulator' -derivedDataPath ../build/swift-consumer CODE_SIGNING_ALLOWED=NO build
```

Android 使用真实 Robolectric Window 验证 owner 叠加、已有 flags、幂等释放和独立窗口。OHOS 真实 ArkTS 源码转译后 mock Window 验证异步获取、释放、恢复失败重试。Swift `ios/Tests/run.sh` 编译真实策略源文件与 UIKit mock，覆盖跨 controller owner、捕获状态通知、窗口转移和初始 idle-timer；mock 不能替代 UIKit 设备行为。Swift Package 和独立 Package consumer 另以真实 iOS Simulator SDK 编译链接；CocoaPods 独立工程消费同一原生源码。HAR 独立 consumer 从打包 HAR 安装，不引用 ArkTS 源码目录。

Android / iOS / OHOS 真实设备的常亮、录屏/镜像、窗口切换与退出恢复需要设备验收；iOS 静态截图不受保护。各项结果记录于候选验收，不把编译或 mock 通过作为设备验收。


CocoaPods 本地独立消费者生成后运行（Ruby 环境须可加载 `xcodeproj`）：

```sh
ruby verification-ios/create-pod-consumer.rb
cd build/pod-consumer
pod install
xcodebuild -workspace WindowPolicyConsumer.xcworkspace -scheme WindowPolicyConsumer \
  -destination 'generic/platform=iOS Simulator' -derivedDataPath ../pod-consumer-products CODE_SIGNING_ALLOWED=NO build
```

HAR prepublish 使用 `ohpm prepublish <打包HAR路径>`，只校验本地产物，不等于 publish。独立 HAR consumer 临时安装打包 `.har` 后编译，验证结束把 manifest 恢复候选 Registry 坐标；不提交临时 file 依赖。
