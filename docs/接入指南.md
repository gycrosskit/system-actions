# System Actions 接入指南

## 工具链仓库

含 `ohosArm64()` 的宿主使用 OpenHarmony Kotlin `2.2.21-1.0.0`，普通 Kotlin `2.2.21` 不提供该 target。该插件和厂商适配依赖需要对应仓库；在 `settings.gradle.kts` 顶部配置：

```kotlin
pluginManagement {
    repositories {
        maven { url = uri("https://maven.eazytec-cloud.com/nexus/repository/maven-public/") }
        google()
        mavenCentral()
        gradlePluginPortal()
        maven { url = uri("https://mirrors.tencent.com/nexus/repository/maven-public/") }
    }
}
```

依赖仓库与版本见 [README](../README.md#安装)。Android/iOS 的原生能力不依赖 Kuikly；KMP `ohosArm64` Core 只提供公共契约，实际实现需连接原生 HAR 或 Kuikly 模块。

## Android / iOS

Android 使用 `AndroidSystemActions(context)`，iOS 使用 `IosSystemActions()`，通过 `SystemActions` 调用：

```kotlin
import io.github.gycrosskit.systemactions.ActionResult
import io.github.gycrosskit.systemactions.SystemActions

// actions 由 AndroidSystemActions 或 IosSystemActions 创建；在宿主协程中调用。
val result = actions.dial("+86 138-1234-5678")
actions.openExternalUrl("https://example.com/help")
actions.openAppSettings()
actions.openLocationSettings() // Android 系统定位服务设置；iOS 返回 Unavailable
actions.openAppStore(storeListingUrl) // 宿主提供对应平台的 HTTP(S) 详情地址
```

`ActionResult.Requested` 只代表系统已受理；`InvalidInput` 表示输入被拒绝；`Unavailable` 表示系统无法打开。Android 使用 ACTION_DIAL，不申请直接呼叫权限；iOS 等待 UIApplication completion 回执。Android Application Context 自动加新任务标记。系统动作均在主线程发起，协程取消不能撤回已经打开的系统页面。

拨号仅允许开头可选 `+`、数字及空格/括号/连字符，长度最多 31 位可见号码字符（不含开头 `+`）；拒绝 USSD、等待符和传入完整 tel URI。URL 必须包含 HTTP(S) 协议和有效主机，拒绝凭据、空白/控制字符、反斜线、无效转义及非法端口。国际化域名请提供 ASCII/Punycode URL。业务白名单必须由宿主在调用前检查。

`openLocationSettings()` 在 Android 使用 `Settings.ACTION_LOCATION_SOURCE_SETTINGS`，保留主线程、Application Context 的 NEW_TASK 与实际受理/拒绝回执；普通应用设置不能替代定位服务设置。iOS/HarmonyOS 没有当前支持的独立公开入口，返回 `Unavailable` / `unavailable`，不使用未公开 scheme，也不打开其他页面后报成功。接口默认实现返回 `Unavailable`，现有自定义 SystemActions 实现可继续编译。

原生商店 API 自 Maven `0.1.3` / HAR `0.1.2` 提供，历史结果保留在验收记录。本轮 Maven 模块分别为 `com.github.gycrosskit.system-actions:system-actions-core:0.2.0-rc.3` 和 `com.github.gycrosskit.system-actions:system-actions-kuikly:0.2.0-rc.3`，HAR 同为 `0.2.0-rc.3`。JitPack 已公开；OHPM 审核中，精确 Registry 安装尚不可用。产物消费状态见 [rc.3 远程验收](../verification/rc3远程发布验收.md)。

```kotlin
// 以下 API 自 Maven 0.1.3 / HAR 0.1.2 提供。
actions.openNativeAppStore() // Android 当前包 / OHOS 当前 bundle；iOS Unavailable
actions.openNativeAppStore("com.example.app") // 可选显式应用标识
```

`openAppStore(listingUrl)` 仍只接受 HTTP(S)，可能由商店或浏览器处理；iOS 宿主继续提供原商店 URL。`openNativeAppStore(applicationId: String? = null)` 是独立的原生入口，null 使用当前应用标识，显式空白、URI 或不合法的分段标识返回 InvalidInput；iOS 明确返回 Unavailable，旧自定义实现通过默认实现保持兼容。

Android 规范化 `Build.MANUFACTURER` 后明确匹配 Huawei、Honor、Xiaomi/Redmi、OPPO/OnePlus/realme、vivo、Meizu、Samsung，保留各商店 URI 顺序。荣耀允许华为、OPPO 系允许旧商店作为次选，之后依次尝试应用宝、360、百度、Google Play。每次 Intent 都限定固定包名，解析包名必须一致；调用实际成功才 Requested，不使用隐式 market Intent 或网页兜底。查询包名随 AAR Manifest 合并，无需宿主重复声明。厂商协议沿用当前消费宿主行为，真机兼容仍需验收。

## HarmonyOS

```sh
# 审核上架后使用；当前精确版本安装仍 NOTFOUND
ohpm install @gycrosskit/system-actions-native@0.2.0-rc.3
```

```typescript
import { SystemActions } from '@gycrosskit/system-actions-native';
const actions = new SystemActions(uiAbilityContext);
const result = await actions.dial('+86 138-1234-5678');
await actions.openExternalUrl('https://example.com');
await actions.openAppSettings();
await actions.openAppStore(storeListingUrl);
```

返回 `requested` / `invalid_input` / `unavailable`，只在系统 Promise 成功后返回 `requested`。在 UIAbility 主线程使用，context 生命周期由宿主管理，不将页面 context 放入全局单例。拨号走系统拨号界面；应用设置使用 API 22 支持的系统设置协议。库不申请额外业务权限。

旧 HAR `0.1.1` 已发布；原生商店 API 自 [HAR `0.1.2`](https://github.com/gycrosskit/system-actions/releases/tag/har-0.1.2) 提供。该历史归档完成过独立安装/编译，当前 OHPM 公开元数据已列出 `0.1.2` 且 `latest=0.1.2`。本轮包含 Window 修复的 `0.2.0-rc.3` 仍审核中，精确 Registry 安装返回 `NOTFOUND`；审核期间消费固定 Release HAR。`loadProduct` 返回 void，只有 `onAppear` 返回 requested；`onError`、显示前 `onDisappear`、调用异常和 20 秒无回执返回 unavailable。每次请求只完成一次并清理 resolver/timer，迟到事件无效。SDK 没有撤销接口，取消只结束等待，不能声称关闭已显示的商店页面。

下面 API 自 HAR `0.1.2` 开始提供；本轮使用 `0.2.0-rc.3`，旧 Registry `0.1.1` 不提供这些方法：

```typescript
await actions.openNativeAppStore();
const request = actions.requestNativeAppStore("com.example.app");
request.cancel(); // 只结束本次等待，不销毁共享 actions
await request.result; // unavailable
```


## Kuikly OHOS 桥

在共享模块 `build.gradle.kts` 添加：

```kotlin
kotlin {
    sourceSets {
        ohosArm64Main.dependencies {
            implementation("com.github.gycrosskit.system-actions:system-actions-kuikly:0.2.0-rc.3")
        }
    }
}
```

Kotlin `SystemActionsModule` 实现 `SystemActions`，覆盖拨号、HTTP(S) 外链、应用设置、定位设置、HTTP(S) 商店地址与原生商店。页面在 `createExternalModules()` 注册同一实例：

```kotlin
import io.github.gycrosskit.systemactions.kuikly.SystemActionsModule
private val actions = SystemActionsModule()
override fun createExternalModules() = mapOf(SystemActionsModule.NAME to actions)
// 在该页面的 Kuikly 协程上下文中调用 actions.dial(...) 等 API。
// 页面销毁时调用 actions.dispose()；它取消所有等待并移除 Kuikly callback。
```

ArkTS 宿主在 Renderer 的 `getCustomRenderModuleCreatorRegisterMap()` 注册：

```typescript
import { SystemActions, GycSystemActionsModule } from '@gycrosskit/system-actions-native';
// 每个页面持有 actions，原生调用与 Renderer 共享这个实例，不放入全局单例。
const actions = new SystemActions(uiAbilityContext);
modules.set(GycSystemActionsModule.MODULE_NAME, () => new GycSystemActionsModule(actions));
```

两侧模块名均为 `GycSystemActionsModule`。系统调用只委托注入的 SystemActions；URL/拨号校验与平台跳转均不在桥中重复。Renderer 等待系统 Promise 回执后返回 `requested` / `invalid_input` / `unavailable`。Kotlin 单次等待最多 20 秒，超时返回 `Unavailable`；外部协程取消继续传播取消。取消和 `dispose()` 发送对应 requestId 的取消指令，两侧移除 callback；Renderer 的 `onDestroy()` 清空等待并释放实例引用。迟到回调不会交给旧页面，但取消无法撤回系统已打开的页面。

Renderer 为原生商店请求保存本次 cancel 函数；取消、Kotlin dispose 和 Renderer onDestroy 清理自身等待/计时器，重用 requestId 不会接收旧请求回执。共享 SystemActions 的其他原生 owner 不受影响。键盘/环境观察通过 Module 注册和释放；主题界面、消息与退出任务仍由宿主决定。

平台契约依据：[Huawei 展示应用详情页面](https://developer.huawei.com/consumer/cn/doc/doccenter-capabilities/appgallery-productview-loadproduct)、[Android AAR 包可见性声明](https://developer.android.com/training/package-visibility/declaring)。

## Window 策略

以下 API 自 `0.2.0-rc.1` 开始提供。本轮 Maven/HAR 使用 `0.2.0-rc.3`，Swift Package/Git Pod 使用已验 `0.2.0-rc.2`；最新远程消费与 OHPM 审核状态见 [rc.3 远程验收](../verification/rc3远程发布验收.md)。不改变已有 SystemActions API；三个平台的业务录屏授权依旧由宿主提供。

### Android

直接依赖 Core 的 Android 变体。`AndroidWindowPolicy.acquire(window, keepScreenOn = true, screenRecordingAllowed = false)` 返回 `AndroidWindowPolicyLease`，宿主在 `DisposableEffect` 或 Activity 安装时 acquire，`SideEffect` / 状态回调调用 `update(Boolean)`，离开时 `close()`。禁止在可被放弃的 Compose composition 中 acquire。所有方法要求主线程，关闭后的更新无效。

同一个 Window 的 lease 共用进入前 flags，任意 owner 禁录就保留 secure；已有 `FLAG_SECURE` 不因许可而清除。最后一个 owner 关闭后只恢复 `FLAG_KEEP_SCREEN_ON` / `FLAG_SECURE`，不影响其他 flags。常亮取“初始常亮或任一 owner 请求”。策略运行期间宿主应通过 lease 更新这两个 flags，避免平行直接写造成所有权冲突。

### iOS 原生 Package / CocoaPods

独立 UIKit 源码不 import Shared，不需要 KMP Framework。Swift Package 通过仓库 Git tag `0.2.0-rc.2` 或本地 package 路径安装，product `GYCWindowPolicy`。CocoaPods 通过 `pod 'GYCWindowPolicy', :git => 'https://github.com/gycrosskit/system-actions.git', :tag => '0.2.0-rc.2'`或 `:path => '<本地组件检出>'` 安装；这不是 CocoaPods Specs Registry 上架声明。

在 MainActor 创建 `WindowPolicyController(windowResolver:)`，提供当前宿主窗口；`acquire(keepScreenOn: true, screenRecordingAllowed: false)` 返回 lease，后续 `update(screenRecordingAllowed:)` / `end()`。Shared 协议适配器仍在宿主，调用组件时使用已有主线程入口。所有 controller 共用进程 idle-timer owner 集合，最后一个释放才恢复初值；不要依赖 deinit 释放。默认禁录，仅当前 Window 的 screen `isCaptured` 为 true 时安装黑色遮罩，监听公开 `UIScreen.capturedDidChangeNotification`。相同窗口任何 owner 禁录时保留遮罩，窗口变化后宿主调用 `refresh()` 重新解析并移动遮罩；resolver 暂时返回 nil 不会添加遮罩，宿主须在视频显示前保证窗口可解析。

公开 UIKit 无法提前拦截静态截图。黑遮罩只处理录屏/镜像期间视觉内容，不暂停音频或网络，不是加密 DRM。库不使用私有 API，也不把录制状态推导为截图被阻止。

### HarmonyOS HAR

`WindowPolicyController.shared` 延续同一 Ability 的共享窗口所有权；不同 Ability 应分别持有 controller 实例。同一 Ability 所有视频节点必须使用同一 controller，不创建平行控制器。宿主 `module.json5` 声明 `ohos.permission.PRIVACY_WINDOW`，库不代替 Ability 声明权限。宿主注入 `() => Promise<window.Window>`，类型从 HAR 入口一并导出。`createLease` 不获取窗口；首个 `await lease.update(false)` 成功后才展示视频。后续 `update(allowed)` 处理服务端策略；`release()` 即时标记已释放并返回串行恢复 Promise，宿主需要等待或明确捕获失败。

初始 privacy 为 true 时许可不能降低保护，多个 owner 任意禁录即保护，最后一个释放恢复初值。窗口异步获取完成后再次检查释放标志，销毁页面的迟到结果不会改窗口。已发出的系统 setWindowPrivacyMode 无法取消，但 release 排在同一队列后恢复；失败不阻断后续操作，restore 失败保留初值/窗口，可再次 release 重试。库不显示视频、不吞业务错误，策略失败时由宿主停止/隐藏视频。全屏、方向与系统栏目标由宿主输入，fullscreen lease 共用同一 controller 执行与恢复；商城导航仍由宿主管理。


OHPM 审核期间，manifest 仍声明 `@gycrosskit/system-actions-native: 0.2.0-rc.3`，先下载固定 Release HAR 并校验再 `--no-save` 安装；不把机器绝对路径写入版本控制。当前 OHPM CLI 支持 `<har file>`，不支持把该 GitHub URL 直接当作依赖地址：

```sh
curl -fL --retry 3 -o SystemActionsNative.har https://github.com/gycrosskit/system-actions/releases/download/0.2.0-rc.3/SystemActionsNative.har
printf '%s  %s\n' be9848a78a1c9b801d025d45a3fb2961f5f38913f21e6f14ec73ee9c1cbe4051 SystemActionsNative.har | shasum -a 256 -c -
```

## 系统边界迁移（0.2.0-rc.2）

以下 API 已随 `0.2.0-rc.2` 预发布提供；Maven、固定 Git 标签的 Swift Package / Git Pod 已通过实际远程消费者编译和链接。OHPM 仍在审核，使用同版 Release HAR 时须核验 SHA，不将其视为 Registry 验收。

### Android 剪贴板与私有文件

```kotlin
val files = AndroidFileActions(activity)
files.copyText(value, label = "debug-tools")
files.shareFile(File(path), authority = "${activity.packageName}.fileprovider",
    mimeType = "application/zip", title = shareTitle)
```

在主线程调用，结果使用现有 `ActionResult`。`Requested` 只表示剪贴板/chooser 受理，不表示用户已完成分享。
宿主保留唯一 FileProvider、`exported=false`、`grantUriPermissions=true` 和最小私有目录 paths；库不会额外声明 provider。
分享包含同一 content URI 的 `EXTRA_STREAM` 和 `ClipData`，仅 `FLAG_GRANT_READ_URI_PERMISSION`，不授予写入/持久权限。
文件不存在、provider 未配置或系统拒绝返回 `Unavailable`；authority/MIME 为空返回 `InvalidInput`。

### iOS 分享与线程/容器解析

```kotlin
// 主线程。resolver 由宿主桥接实际根与当前顶层控制器。
val files = IosFileActions(presenterResolver)
files.copyText(value)
val accepted = files.shareFile(path, shareTitle) { outcome ->
    // FileShareOutcome.Completed / Cancelled / Failed 来自真实系统 completion。
}
files.close() // 页面销毁：仅关闭本实例面板，并一次性回报 Cancelled。
```

只接收现有普通文件，每个实例同时一个面板；未附着窗口/正在转场的 presenter 返回 `Unavailable`。
iPad popover 锚定当前 presenter 的 view 中心，关闭和 completion 清理回调引用。`ActionResult.Requested`
表示面板受理，与 `FileShareOutcome` 终态分开，宿主不把受理显示成“分享成功”。

```swift
import GYCWindowPolicy
UIKitExecutionContext.run { /* 已在主线程时同步执行 */ }
UIKitExecutionContext.runOnMainActor { /* MainActor 操作 */ }
let nativeView = UIKitExecutionContext.syncOnMainActor { /* 必须同步返回的原生对象 */ }
let presenter = UIKitPresentationContext.topViewController(from: appRoot) { controller in
    (controller as? ActiveChildViewControllerProviding)?.activeChildViewController
}
let currentWindow = UIKitPresentationContext.activeWindow
```

三个执行 API 保留生产同步语义；同步闭包不得含阻塞任务。系统 Scene/模态/Nav/Tab/Split 算法属于组件，
`appRoot` 与自定义 active-child 属于宿主。无 root 参数时即时读取当前 active Window；不缓存旧 Scene。
未使用的宿主 `dismiss` 不发布。原生 product/pod 名称仍为 `GYCWindowPolicy`，无需新 presentation 库。

### OHOS 键盘和环境观察

Kotlin `SystemActionsModule` 增加 `observeKeyboardHeight(onChange: (Float) -> Unit): () -> Unit`、
`observeDarkMode(onChange: (Boolean) -> Unit): () -> Unit`、公开 `stopKeyboardHeight()` / `stopDarkMode()`。
同页原生直接注册既有 `GycSystemActionsModule(actions)`，不再注册宿主键盘/环境实现。

```kotlin
val stopKeyboard = actions.observeKeyboardHeight { heightVp -> /* 宿主消费 inset */ }
val stopDark = actions.observeDarkMode { dark -> /* 宿主选择主题 */ }
stopKeyboard()
stopDark()
actions.dispose() // 同时撤销原生 listener 与 Kotlin callback token
```

高度使用所绑定 Window 的 `px2vp`；默认初值为 0。配置读取与 EnvironmentCallback 都由组件执行。
重复 observe 替换旧监听；旧 stop token、迟 Window、注册失败和 off 后排队回调不会交给旧页面。
环境初始回调中 stop/dispose 也不会重新注册；不持有 App 主题 state 或导航 owner。

### OHOS 全屏窗口与 WebView 接线

```typescript
const fullscreen = WindowPolicyController.shared.createFullscreenLease(
  () => window.getLastWindow(context),
  {
    enterOrientation: width <= 0 || height <= 0 || width > height
      ? window.Orientation.AUTO_ROTATION_LANDSCAPE : undefined,
    unspecifiedExitOrientation: window.Orientation.PORTRAIT,
    enterSystemBars: [],
    exitSystemBarsWhenFullscreen: [],
    exitSystemBarsWhenNotFullscreen: ['status', 'navigation']
  },
  () => { /* 旧 WebView 立即退出自己的 FullScreenExitHandler，并发出 false */ }
);
const entered = await fullscreen.enter();
await fullscreen.exit(); // 返回/后台/不可见，同一入口；可再 enter
await fullscreen.release(); // 销毁，后续 enter 返回 false
```

`FullscreenWindowPolicy` 可选 `enterLayoutFullscreen` / `exitLayoutFullscreen`；省略则不主动修改布局。
未指定退出方向时，仅在本轮接管曾修改方向的情况下恢复首次接管前方向；layout-only 接管不会回写方向。
显式 exitOrientation 或原 UNSPECIFIED 时的 unspecifiedExitOrientation 仍会执行宿主退出目标。
未指定退出系统栏时按 FullScreen 状态恢复；宿主应输入当前页面目标，
生产策略仅在原方向 UNSPECIFIED 时用宿主 unspecifiedExitOrientation=PORTRAIT，其他原值原样恢复；
接管前 isFullScreen=true 时按 exitSystemBarsWhenFullscreen=[] 恢复，false 时按
exitSystemBarsWhenNotFullscreen=[status,navigation] 恢复。显式 exitOrientation/exitSystemBars 优先。
这些目标由宿主输入，库不决定普通页方向或系统栏外观。
全屏最新 owner 接管，旧 owner 的 onReplaced 通知用于关闭其 WebView handler。所有 Window 操作与 privacy
lease 共用唯一 controller 的串行队列；每次 enter 有独立 revision，旧 View/旧 enter 不恢复或继续执行新任务。
退出等待正在执行的系统调用完成后恢复；恢复失败保留初始状态并允许再次 exit/release 重试。

删除宿主 `AppGYWebView` 的静态 fullscreen owner、窗口引用/初值、每 View task 队列和 orientation/bar 调用；
WebView 只持 handler/lease、转接事件及生命周期。背景、第一返回、隐藏、销毁统一 exit/release，
系统受理与事件终态由实际 Promise 返回决定。privacy lease 保留原 API，不另建全屏 controller。
