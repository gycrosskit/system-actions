## 实际远程消费

在独占 Worktree 的忽略 `build/remote-maven-0.1.3` 新建独立消费者，复制现有 `verification-consumer` 的配置与探针源码。仓库仅使用 JitPack 和上游依赖仓库，没有 `includeBuild`、源码 project、`mavenLocal`、本地 staging 或 init script 替换。

```sh
bash gradlew -p build/remote-maven-0.1.3 \
  compileDebugKotlinAndroid compileKotlinIosArm64 compileKotlinIosX64 \
  linkDebugFrameworkIosSimulatorArm64 compileKotlinOhosArm64 \
  --rerun-tasks --max-workers=1 -Dorg.gradle.jvmargs=-Xmx2g \
  -Pkotlin.compiler.execution.strategy=in-process --info
```

使用本机 JBR 21 与 Android SDK 36，47 秒、13 个任务全部执行成功。日志含 Maven `0.1.3` Android AAR 与 iOS arm64/x64/Simulator、OHOS core/Kuikly KLIB 的 JitPack 下载记录；Simulator Framework 实际链接生成。日志在忽略目录 `build/remote-maven-0.1.3/remote-build.log`。一次无效 JDK 路径启动失败与一次 DevEco JBR 25 不兼容失败后，切回已有 JBR 21 重跑通过。

HAR 在另一独立目录 `build/remote-har-0.1.2` 从 GitHub Release 下载归档并校验，临时子模块 `file:../download/SystemActionsNative.har` 依赖安装成功，`hvigorw assembleHar --no-daemon` 成功，30 个任务全部执行。这只证明远程归档消费。日志 `archive-install.log` / `archive-build.log` 保留在该忽略目录；正式 `verification-ohos` 仍声明精确 Registry 版本 `0.1.2`。

## OHPM 门禁

第一次 `ohpm publish` 被 Registry HTTP 400 拒绝，原因是 README 缺少 `ohpm install` 命令，未接受发布。PR #10 修正、重新打包并通过 `prepublish` 后，最终 `publish` 输出 `+@gycrosskit/system-actions-native 0.1.2` 及 `under review`。最终产物即上述独立 HAR Release。

本轮真实执行 `ohpm info @gycrosskit/system-actions-native versions` 仅列出 `0.1.0 / 0.1.1`；精确 `0.1.2` Registry 清单执行 `ohpm install --all` 返回 `NOTFOUND`。不能称为已上架或 Registry 安装通过，不重复提交同版发布。审核状态入口为[OHPM 包管理](https://ohpm.openharmony.cn/#/cn/personalCenter/package)。

审核通过后仍须以精确 Registry `0.1.2` 清单在干净工程中安装、核验锁文件 `resolved` 指向 `ohpm.openharmony.cn`，并重新 `assembleHar`。目前仅归档消费已通过，Registry 门禁尚未通过。

未执行 Android/iOS/OHOS 真机商店页面与真实 Kuikly 页面生命周期验收。编译、mock、归档消费与 Release 发布均不能代替这些设备验收。
